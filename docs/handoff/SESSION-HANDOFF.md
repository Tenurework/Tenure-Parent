## 2. The number that matters, and the one that lies

`PASS` is read from an execution ledger, never from a Bible's own checkbox. The
registry (`docs/architecture/capability-completeness-registry.yaml`) is
GENERATED by `tools/document-graph.mjs`. Editing it does nothing.

**"Decided" is not "done."** 1,461 requirements have a ledger row; 320 of them
pass. A status report quoting the first number is wrong by a factor of four.

**A claimed PASS is not a PASS.** Three fan-outs produced 85 confirmed and 50
overturned. That overturn rate is not agents being sloppy — it is one specific
failure that a refuter catches and nothing else does:

> a requirement closed against a narrower reading of itself

Verbatim from refuters:

- *"REFUTED ON REQUIREMENT SCOPE, not on execution quality. Everything
  mechanical checks out."*
- *"the requirement says locate EVERY hard-coded assumption; the scan does not
  locate the pilot's own role vocabulary."*
- *"three of the nine prohibitions are not prohibited."*
- *"build twenty-two accessible primitives"* — closed on eleven.

A mutation proof shows a test CAN fail. It says nothing about whether the thing
proven is the thing asked for. **Always run the refute phase. Never tick a box a
refuter has not confirmed.**

## 3. How to run a wave

`tools/loop/*.mjs` are workflow scripts. The three that worked:

- `family-fanout.mjs` — one agent per family (12 families)
- `big-family-fanout.mjs` — slices of the six biggest (12 slices)
- `wave3-fanout.mjs` — 16 slices including the mid-size families

Copy one, edit the `SLICES` array, launch with
`Workflow({scriptPath: "tools/loop/<name>.mjs"})`.

### Four rules that make a wave work

1. **Agents must NOT write ledgers.** They return rows as data; the orchestrator
   writes them, and only for confirmed claims. Wave 1 let agents write their own,
   and 18 unconfirmed claims landed as `Status: PASS` — the count said 42 closed
   where 24 were, and correcting it was a separate pass.
2. **Prefer requirements provable without a build.** `npm run studio:build` is
   ~350s and a rendered page needs a server. Waves 2 and 3 had ZERO agents build,
   which is the only reason 32 could run at once.
3. **No schema changes.** An earlier run produced six unverified Prisma
   migrations that had to be quarantined on `wip/ier-killed-run-20260808` and
   never merged. Requirements needing one return `NEEDS_SCHEMA`.
4. **Tell agents to read the overturn reason first.** Wave 3 closed five
   requirements wave 2 had overturned. The refuter's note names the exact clause
   that was missed, which makes it the cheapest item in the slice, not the dearest.

### Writing the rows afterwards — three cases, and you need all three

| Existing row for that id | Action |
|---|---|
| none | append the returned row |
| a SEEDED STUB (`- Reason: imported from <Bible>; not yet implemented`) | **replace** it |
| a real row with evidence, or a FAIL carrying a refuter's finding | **append** — the parser takes the LAST row, and the old one is the history |

Getting the third case wrong silently loses confirmed work: 8 claims in wave 3
did not land until it was handled.

## 4. Mistakes made in that session. Read these; they cost hours.

**I told the owner his AWS keys needed rotating. They did not.** The account was
SUSPENDED. Every symptom followed from that one cause — distributions out of DNS,
static key rejected, OIDC rejected. Suspension was proposed early and then argued
away because the account's Cognito hosted UI answered 200 from a runner. That was
one managed endpoint that had not been reaped yet. **Two independent credential
mechanisms failing simultaneously outweighs one endpoint still answering.**

**I diagnosed a dead CloudFront distribution from a machine that cannot reach
CloudFront.** The operator's network returns nothing for every `*.cloudfront.net`
name — including one I invented. Google and Cloudflare DNS-over-HTTPS returned
`NOERROR` with zero answers for the invented name too, so the method could not
distinguish live from dead. **Local reachability evidence about this estate is
worthless. Use a GitHub runner** — `.github/workflows/reachability.yml` exists for
exactly this and needs no credentials.

**I reported a plan from an eleven-day-old workflow run as if it were mine.** The
dispatch had been rejected with HTTP 422; I read the previous run's log without
checking its timestamp.

**I wrote a shell step that reported "0 distributions match" when the truth was
that no call had been made** — reintroducing in bash the empty-versus-unknown
confusion this whole codebase exists to prevent.

**I "fixed" a spec after misreading which assertion failed.**
`search-reports.spec.ts` failed on Isaiah, the SHADOW president — not on Priya.
The spec was asserting the defect `HCM-040-003` deliberately removed.

**I hardcoded a floor and caught myself only afterwards.** Wrote `>= 28` for a row
budget with no measurement behind it — the exact thing I had been correcting
agents for. It happened to be right. That is luck, not method.

## 5. Traps in this repository

**A green `tsc --noEmit` is not a green build.** `next build` type-checks the
inferred shape of imported JSON at the point of use. `platform-truth.json` is
imported, so an EMPTY array infers as `never[]` and `d.call` fails to compile. The
build broke on the healthiest possible state — an estate that was refused nothing.
Type imported-artefact arrays explicitly.

**Some guards are literal about SHAPE, not just behaviour.**
`states-logic.spec.ts` matches `const denied = ...estate.`; putting a type
annotation between the name and the `=` breaks it. The guard is right — it checks
that the page still READS the inventory, which no type can show.

**A detector finding zero of anything is not passing, it is dead.** Two guards in
wave 3 reported "found 1" and "no offered values found". Both carry a floor
asserting they must find SOMETHING, and that floor is the only reason either was
caught. **Never lower such a floor. Fix the matcher.**

**Ratchets exist and are argued in prose.** `SHARED.size`, `ROWS_PER_FOLD`,
`MEMBERSHIP_ONLY_GATE_COUNT`, the TTES debt budgets. Several may only fall. If one
genuinely must move, move it and argue it in the file the way its neighbours are
argued.

**Do not calibrate a test to this machine.** Two specs went green locally and red
in CI on absolute pixels that depend on content and font metrics. A row count is
data; a line-height times a font size is arithmetic. Assert the arithmetic.

**Wait, then measure.** `boundingBox()` samples once and returns null for anything
unpainted; `expect(x).toBeVisible()` retries. Measuring straight after `goto()`
turned CI red twice in one week.

## 6. Operational hazards that cost a whole afternoon

**A running standalone server BLOCKS the next build on Windows.** It holds files
under `.next` open; the build then sits at ZERO CPU emitting no BUILD_ID,
indefinitely. It reads exactly like a slow build on a busy machine. Measured: 25
minutes at 0%, then 210 seconds once the server was stopped. Seven requirements
came back BLOCKED_EXTERNAL from one wave for this, and nobody diagnosed it.

**`output: standalone` copies the project tree, including other agents' scratch
builds.** `.next` reached 12GB against a normal ~677MB, with
`.next/standalone/.../.next-density-budget/standalone` nested inside. Growth is
quadratic in agent count. Fixed by `outputFileTracingExcludes` in
`apps/system-studio/next.config.ts`. Do not remove it.

**The disk filled to 12MB free twice.** The symptom is not an out-of-space error.
It is a suite reporting a different number of tests on every run and failing
somewhere new each time — which reads as flakiness and gets waited on. Check
`df -h /c` before blaming a test.

**Agents leave `.next-*` entries in `apps/system-studio/tsconfig.json`.** Strip
every one before committing. A guard catches it, but only after CI has run.

## 7. CI, and the one thing that is not obvious

Eight jobs. `Deploy Studio` fires on `workflow_run` after CI concludes and refuses
to run unless CI passed. That gate is load-bearing: it was added because the
console had been rolling from builds whose own suite was red.

**`actions/checkout` clones at depth 1, and five absorption tests read a commit
reachable only from `satvikOS/Tenure`.** They pass on any laptop that has run
`git fetch live` and fail on every runner. `ci.yml` now fetches each pinned commit
before the platform tests, trying `origin` then `live`, with the shas read out of
the committed snapshots — so re-pinning a baseline carries the step with it.

The tempting fix was to let those tests degrade quietly the way
`simon-absorption-inventory.test.mjs` does — diagnostic, continue, report green.
Do not. They are what catches a schema drifting from the tree it was absorbed from.

## 8. Skips — the honest position

- **Nothing is hard-disabled.** No `xit`, no `.skip(true)`, no `.todo`.
- **37 conditional skips** across 14 Studio specs, shaped
  `test.skip(!configured, "needs TENANT_TABLE and a reachable DynamoDB")`.
- CI's Studio job sets `TENANT_TABLE`, creates the registry table and seeds the
  fleet, so they do not fire there.
- **They absolutely fire locally.** The same two specs report 43 passed / 17
  skipped without `TENANT_TABLE`, and 60 passed / 0 skipped with it. A local run
  that forgets one variable reports green while testing a third less than it
  appears to. Export the whole harness block, every time.

## 10. Rules that are not negotiable

- **Never push to `github.com/satvikOS/Tenure`.** A push to its main rolls
  production for a live pilot carrying real student data. Open a PR.
- **The production workflows here stay disarmed.** Every AWS-touching job carries
  `if: github.repository == 'Tenurework/Tenure'`. It working is the failure mode.
- **Only a refuter-confirmed requirement gets ticked.**
  `tests/architecture/a-ticked-box-is-a-passing-requirement.test.mjs` enforces
  this, and it exists because a box was ticked for a requirement whose three
  ledger rows included one titled "this row does NOT close the requirement".
- **Report what you ran, not what you expect to pass.**
