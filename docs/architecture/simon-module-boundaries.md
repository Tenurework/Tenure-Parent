Core production files importing the tenant registry: **3** — known, named, and shrink-only. SIMON-010-008 stays FAIL while any remain.
- `packages/generality-fixtures/src/corporate-org.ts:1` — imports the tenant-specific export `TENANT_BINDINGS`. **not on the known list**
- `packages/platform-config/src/modules.ts:1` — imports the tenant-specific export `TENANT_BINDINGS`. `modulesForEveryTenant` maps the registry; the fleet view belongs to the composition edge, and this function should take the bindings as an argument
- `packages/platform-config/src/resolve.ts:10` — imports the tenant-specific export `TENANT_BINDINGS`. `systemConfigForEveryTenant` maps the registry; same shape, same fix

A slug-parameterised resolver is on neither list and is not prohibited. `getTenantBinding(slug)` is how a tenant arrives as an argument; forbidding it would forbid the platform from resolving anybody.

Core production files that import tenant configuration AND name a tenant: **0** — prohibited. This is the conjunction the bible's §2 calls Simon-aware core business logic.
